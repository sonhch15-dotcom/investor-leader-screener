처리는 v0.5에서 변경하지 않는다.

## 월별 커버리지 판정

월 `m`은 다음을 모두 충족할 때만 `COVERAGE_ELIGIBLE`이다.

```python
MIN_OVERALL_COVERAGE = 0.90
MIN_SECTOR_COVERAGE = 0.80
REQUIRED_PROVENANCE_RATE = 1.00
CALIBRATION_MONTHS = 60
```

- 전체 포함 발행사 판정 가능 비율 90% 이상
- 모든 포함 GICS 섹터의 판정 가능 비율 80% 이상
- 판정에 사용한 사실의 공시일·접수번호 존재율 100%
- 당시 S&P 500 구성 발행사와 당시 공시된 point-in-time 사실만 사용
- Financials, Real Estate, Utilities 제외
- 자기자본 0 이하는 자동 미통과이므로 판정 가능 수에 포함
- 데이터 결측 또는 구성 이력 결측을 적격으로 간주하지 않음

월별 그리드는 SEC 원천과 과거 S&P 500 구성 복원의 공통 가용범위에서
가장 이른 달부터 최신 완결 월까지 빠짐없이 만든다. 중간 월이 없으면
그 월은 미달이며 연속 적격 개월 수를 0으로 되돌린다. 조회 시작월을
늦춰 더 이른 실패 월을 숨기지 않는다.

## 최초 백테스트 신호월

최초 신호월은 다음 단일 규칙으로 결정한다.

> 최초 백테스트 신호월 = 직전 60개 연속 월말이 모두
> `COVERAGE_ELIGIBLE`인 가장 이른 달

정확한 절차는 다음과 같다.

1. 월별 커버리지 행을 오름차순으로 정렬한다.
2. 달력상 연속된 적격 월의 길이를 센다.
3. 최초로 60개월 연속 적격이 완성된 월을 보정기간 종료월로 정한다.
4. 그 다음 달을 최초 신호월로 정한다.
5. 더 늦은 기간의 커버리지가 더 높아도 최초 신호월을 옮기지 않는다.
6. 최초 신호월 이후 후보 수나 수익률을 보고 날짜를 조정하지 않는다.
7. 전체 가용범위에서 60개월 연속 적격 구간이 없으면
   `NO_VALID_BACKTEST_START`로 판정하고 수익률 계산을 시작하지 않는다.

가장 이른 적격 월을 택하는 이유는 평가 표본과 시장 국면의 수를
기계적으로 최대화하기 위해서다. 특정 연도의 시장 성과나 전략 성과는
선택에 사용하지 않는다.

## 보정기간과 평가기간은 겹치지 않는다

최초 신호월 직전 60개 월은 오직 다음에만 사용한다.

- 과거 월별 데이터 유효성 확인
- 연결 총부채비율 P50 절대 임계값 계산

이 60개 월에는 신호를 생성하지 않고, 포트폴리오·이벤트 수익률,
승률, 초과수익, 강건성 조합 또는 신뢰구간을 계산하지 않는다.
보정기간의 마지막 월 다음 달부터 평가기간이 시작된다.

보정기간의 재무 관측치는 임계값 보정에만 포함되고 성과 표본에는
포함되지 않는다. 경계 월을 양쪽에 중복 배정하지 않는다.

## 보유기간별 마지막 신호월과 우측 검열

세 보유기간 트랙은 독립적으로 운용한다.

```python
HOLDING_PERIODS = (63, 126, 252)
ENTRY_TIMING = "NEXT_TRADING_DAY_OPEN"
EXIT_TIMING = "H_TH_TRADING_SESSION_CLOSE"
```

월별 신호일은 해당 신호월의 마지막 정규 NYSE 거래일이다. 진입일은
신호일 다음 정규 NYSE 거래일이며 시가에 진입한다. 진입 세션을 1일째로
세어 `H`번째 정규 거래일 종가를 종료 관측점으로 사용한다.

각 트랙의 마지막 신호월은 다음과 같다.

> 마지막 신호월(H) = H번째 거래일 종가가 데이터 기준일 이내에 존재할
> 수 있는 가장 늦은 월별 신호월

- 63·126·252거래일 트랙은 서로 다른 마지막 신호월을 가진다.
- H번째 거래일까지 완결되지 않은 신호는 `RIGHT_CENSORED`로 기록하고
  해당 트랙의 성과 분모에서 제외한다.
- 미완결 신호를 0% 수익이나 실패로 간주하지 않는다.
- 종료일을 맞추려고 보유기간을 줄이거나 다른 트랙으로 옮기지 않는다.
- 데이터 기준일은 가격 파일을 열기 전에 실행 명세에 고정한다.
- 우측 검열 가능성은 공통 NYSE 거래일 달력으로 판정한다.
- 공통 달력상 완결 가능한데 개별 종목 가격이 없으면 우측 검열이 아니라
  `MISSING_SECURITY_PRICE` 데이터 오류로 별도 집계한다.

## 커버리지 조회와 수익률 계산의 물리적 분리

과거 커버리지 조회는 독립 프로그램으로 실행한다. 이 프로그램은
다음 자료에만 접근할 수 있다.

- 과거 S&P 500 구성 이력과 CIK 계보
- SEC FSDS/XBRL 재무사실
- 공시일, 접수번호, 재무기간 말
- GICS 섹터

다음 자료나 기능에는 접근하지 않는다.

- yfinance 또는 다른 가격 API
- 종목·SPY OHLCV, 수정주가와 배당
- 미래 보유수익률, 초과수익, 승률
- 후보 발생 후 수익률
- 63·126·252일 종료가격

커버리지 프로그램의 허용 출력은 월별 분모·판정 가능 수·섹터별
커버리지·provenance·결측 사유·연속 적격 길이·최초 신호월뿐이다.
가격 또는 수익률 열이 출력에 있으면 실행을 무효로 한다.

`historical_coverage_window.py`는 위 출력만 읽어 최초 신호월을 산출한다.
이 모듈은 표준 라이브러리 외 가격·시장 데이터 모듈을 import하지 않는다.
정적 테스트로 금지 import와 금지 출력 필드가 없음을 확인한다.

과거 커버리지 결과와 산출된 최초 신호월을 원격에 커밋·태그한 뒤에만
별도 가격 프로세스를 시작할 수 있다. 같은 명령, 같은 노트북 또는
같은 스크립트 실행에서 커버리지와 수익률을 연속 계산하지 않는다.

## 월별 커버리지 입력 계약

`historical_coverage_window.py`의 입력은 다음 열을 가진 CSV다.

| 열 | 정의 |
|---|---|
| `month` | `YYYY-MM` 달력월 |
| `overall_coverage` | 포함 발행사 전체 판정 가능 비율 |
| `minimum_sector_coverage` | 포함 섹터 중 최저 판정 가능 비율 |
| `provenance_rate` | 사용 사실의 공시일·접수번호 존재율 |

각 월은 한 행이어야 하며 중복 월은 오류다. 비율은 0~1 범위여야 한다.
중간 월 누락은 암묵적으로 적격 처리하지 않고 연속 구간을 끊는다.

출력 JSON에는 다음을 기록한다.

- 입력 파일의 SHA-256
- 적용한 90%·80%·100%·60개월 상수
- 스캔 시작월과 종료월
- 최초 적격 보정기간 시작월과 종료월
- 최초 신호월 또는 `NO_VALID_BACKTEST_START`
- `prices_accessed = false`
- `returns_calculated = false`

## 변경 금지

- 더 긴 표본을 얻기 위해 커버리지 최소선을 낮추지 않는다.
- 최초 신호월이 예상보다 늦다는 이유로 60개월을 줄이지 않는다.
- 중간 미달 월을 제거해 연속 구간을 만들지 않는다.
- 종료 표본을 늘리기 위해 보유기간이나 데이터 기준일을 사후 변경하지
  않는다.
- 커버리지 결과 또는 수익률을 본 뒤 시작·종료 규칙을 바꾸지 않는다.

규칙 변경이 필요하면 현재 실행을 무효로 기록하고 새 가설을 별도
사전등록·원격 태그한 뒤 처음부터 다시 실행한다.
